# [분석] 태스크 축약 가능성 검토

**문서 ID:** ANL-FINFRIENDS-TASK-002

**개정 버전:** 1.0

**날짜:** 2026-08-26

**대상:** TASK-FINFRIENDS-MVP-001 · 태스크 **68건**

**수치 재현:** `python3 tools/analyze_tasks.py`

> **이 문서가 답하는 것** — 태스크 68건이 **너무 잘게 쪼개져 있는가.** 병합 후보를 객관 기준으로 전수 탐색하고, 각각 **병합할지 말지와 그 이유**를 남긴다.
> **결론부터 — 축약하지 않는다. 67건을 유지한다.**

---

## 1. 왜 검토하는가

태스크가 많으면 관리 비용이 든다. 반대로 지나치게 묶으면 **진척이 뭉개지고 담당자를 나눌 수 없다.** 둘 사이의 선을 근거 있게 정해 둔다.

67건은 **레퍼런스 사례(59건)보다 8건 많다.** 그 차이가 정당한지 확인하는 것이 이 검토의 출발점이다.

---

## 2. 우리 이력 — 축약이 아니라 승격이었다

레퍼런스 사례는 118 → 56건으로 **줄이는** 축약을 거쳤다. 우리는 반대였다.

| 시점 | 건수 | 사건 |
| :-: | :-: | --- |
| 최초 도출 | **65** | 반영판 SRS의 구현 단위에서 분해 |
| 커버리지 검사 | 65 | 🔴 **REQ-FUNC-015 · 016에 담당 태스크 없음** 검출 |
| 승격 | **67** | `CON-005`(카드 없는 체험 경로) · `STR-005`(별의 옷장 외 목적지) 신설 |
| 프로토타입 선별 | 67 | 🔴 **목 픽스처 태스크 부재** 검출 — 화면 4건이 같은 목을 쓰는데 담당이 없었다 |
| 신설 | **68** | `MCK-001`(화면용 목 픽스처) · Epic `MCK` 신설 |

**우리는 축약 단계를 거치지 않았다. 두 번 다 늘어났다.** 처음부터 서버 진입점(반영판 §6.1의 19개)을 경계로 삼아 분해했기 때문에 과분해가 일어나지 않았다. 레퍼런스가 118건에서 시작한 것은 다른 분해 기준을 썼기 때문이다.

> 그래서 이 문서는 **「줄인 기록」이 아니라 「줄이지 않기로 한 근거」** 다.

## 3. 병합 후보 전수 탐색

### 3.1 탐색 기준

객관적으로 병합해도 이상하지 않은 조건을 걸었다.

```
같은 Epic  ∧  같은 유형  ∧  직접 의존 관계  ∧  복잡도가 둘 다 L 또는 M
```

**8쌍**이 걸렸다.

### 3.2 판정

| # | 후보 | 선행의 다른 후행 | 판정 | 이유 |
| :-: | --- | :-: | :-: | --- |
| 1 | `INF-001` + `INF-003` | **5건** | ❌ 병합 불가 | INF-001은 앱 골격이라 후행 5건이 더 걸려 있다. 병합하면 **그 5건이 Supabase 연결까지 기다린다** |
| 2 | `INF-001` + `INF-004` | **5건** | ❌ 병합 불가 | 동일. 게다가 PWA는 **X3 결정(오프라인 축소 여부)** 에 걸려 있어 앱 생성과 운명을 같이하면 안 된다 |
| 3 | `LRN-001` + `LRN-002` | 4건 | ❌ 병합 불가 | 출석 조건이 **D5 미결**이다. 병합하면 미결 하나가 **학습 전체를 막는다** |
| 4 | `LRN-001` + `LRN-003` | 4건 | ❌ **절대 불가** | LRN-003은 **D2 법률 검토 블로커**(P-20 중개 회피). 착수 자체가 막혀 있는 것을 Must 태스크와 묶을 수 없다 |
| 5 | `UX-001` + `UX-003` | **5건** | ❌ 병합 불가 | UX-001은 토큰 기반이라 후행 5건이 전부 여기 걸린다 |
| 6 | `UX-001` + `UX-005` | **5건** | ❌ 병합 불가 | 동일 |
| 7 | `UX-001` + `UX-006` | **5건** | ❌ 병합 불가 | 동일 |
| 8 | `CON-003` + `CON-005` | **0건** | ⚠️ **유일한 여지** | 아래 §3.3 |

### 3.3 유일한 병합 여지 — CON-003 + CON-005

기준을 통과한 것은 **한 쌍뿐**이다. 선행(`CON-003` 보호자 온보딩)의 다른 후행이 없어 병합해도 다른 태스크를 지연시키지 않는다.

**그런데도 병합하지 않는다.**

| 근거 | 내용 |
| --- | --- |
| **우선순위가 다르다** | CON-003은 **Must Have**(REQ-FUNC-007), CON-005는 **Could Have**(REQ-FUNC-015). 병합하면 Could가 Must를 지연시킨다 |
| **블로커가 다르다** | CON-003은 **D-03(본인인증 위임)** 에 걸려 있고 CON-005는 걸려 있지 않다. 묶으면 CON-005가 D-03을 기다린다 |
| **진척이 뭉개진다** | 온보딩 5단계 구현과 체험 경로는 완료 시점이 다르다. 하나로 두면 *"온보딩 80% 완료"* 가 무엇을 뜻하는지 알 수 없다 |

## 4. 복잡도 L 4건 — 흡수 가능한가

「설정 수준」으로 분류된 4건을 따로 봤다. 작은 태스크는 흡수 1순위 후보다.

| 태스크 | 후행 | 판정 | 이유 |
| --- | :-: | :-: | --- |
| `LRN-002` 출석체크 | 0 | ❌ 유지 | **D5 미결**을 담고 있다. 흡수하면 미결의 소재가 사라진다 |
| `STR-004` 별↔저금통 정적 검사 | 1 | ❌ 유지 | **규제 게이트**(P-21 · S4)다. 다른 태스크에 딸린 항목이 되면 빠뜨려도 보이지 않는다 |
| `PLN-006` 문장 풀 잔여 배치 | 0 | ❌ 유지 | 담당이 **콘텐츠 담당**이다. 개발 태스크에 흡수하면 수신자가 사라진다 |
| `REL-003` 원가 집계 | 0 | ❌ 유지 | 담당이 **사업 담당**이다. 동일 |

**넷 다 유지한다.** 작다는 것이 흡수의 근거가 되지 못한다 — **담당자가 다르거나, 규제·미결을 담고 있어** 독립 추적이 필요하다.

## 5. 병합을 막는 원칙 5가지

이번 검토에서 실제로 작동한 판정 기준을 규칙으로 남긴다. 다음 판본에서도 같은 잣대를 쓴다.

| # | 원칙 | 근거가 된 사례 |
| :-: | --- | --- |
| **P1** | **후행 수가 다르면 병합하지 않는다** — 후행이 많은 쪽이 늦어진다 | 후보 1 · 2 · 5 · 6 · 7 |
| **P2** | **블로커가 걸린 태스크는 묶지 않는다** — 막힌 것이 안 막힌 것을 막는다 | 후보 3 · 4 · 8 |
| **P3** | **우선순위가 다르면 묶지 않는다** — Could가 Must를 지연시킨다 | 후보 8 |
| **P4** | **담당자가 다르면 묶지 않는다** — 수신자가 사라진다 | PLN-006 · REL-003 |
| **P5** | **BE 구현과 UI 구현을 섞지 않는다** — 리뷰 관점이 다르고 진척 추적이 뭉개진다 | UI 6건 분리 유지 |

## 6. 결론

| 항목 | 결과 |
| --- | :-: |
| 탐색한 병합 후보 | **8쌍** |
| 신설로 늘어난 건수 | **+3건** (승격 2 · 프로토타입 1) |
| 병합 확정 | **0쌍** |
| 복잡도 L 흡수 | **0건** |
| 최종 태스크 수 | **68건 유지** |

**축약하지 않는다.** 8쌍 중 7쌍은 **후행 지연**으로 막히고, 나머지 1쌍은 **우선순위·블로커가 달라** 막힌다.

레퍼런스 사례보다 8건 많은 이유도 여기서 설명된다 — 우리는 **서버 진입점을 경계로 처음부터 분해**했고, 규제 게이트(S1~S6)와 미해소 결정(D-01~D-03)이 각각 독립 태스크를 요구한다. **줄일 여지가 애초에 적었다.**

> ⚠️ **이 결론은 지금의 의존성 구조에 걸려 있다.** 미해소 3건이 닫히면 P2가 풀리는 태스크가 생기므로, **D-01 · D-02 · D-03 처리 후 이 검토를 다시 돌린다.**
>
> 🔴 **`MCK-001` 은 예정된 소멸 대상이다.** 프로토타입 전용 픽스처이므로 백엔드 4건(GRW-002 · GRW-004 · PLN-003 · STR-001)이 완료되면 **역할이 끝난다.** 그 시점에 흡수 또는 제거를 검토한다 — **원칙 P4(담당자)와 P2(블로커)에 걸리지 않는 유일한 축약 후보**가 될 것이다.
