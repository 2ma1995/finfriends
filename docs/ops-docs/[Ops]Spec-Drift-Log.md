```
② 보호자 세션이 죽어도       OK          ← 부모 재로그인 불필요
③ 보호자가 동의를 철회하면   CONSENT_REQUIRED  ← 토큰이 살아 있어도 막힌다
④ 보호자가 기기를 해제하면   REVOKED
```

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 별은 **승인에서만** 생긴다 | 「했어요」(`markDone`)는 `doneAt` 만 찍는다. `grantStar` 는 `approveMission` 안에만 있다. 아이 쪽 액션에서 원장을 건드리지 않는다 — 건드리면 아이가 별을 무한히 만든다 |
| 🔴 중복 지급 0건 | 멱등키가 `mission:<id>` **하나**다. 두 번 눌러도 `P2002` 로 막힌다 (REQ-NF-006) |
| 🔴 소급이 다음 주기를 부풀리지 않는다 | `cycleId` 는 **「했어요」 시점**에 박힌다. 승인은 이 값을 고치지 않는다 (ACE-6.2) |
| 🔴 「승인 대기」 ≠ 「미실천」 | 아이 화면이 세 구역으로 갈린다 — 오늘 할 수 있는 것 / 기다리는 중 / 지난 미션. 거절은 사유를 그대로 보여준다 (AC-6.2) |
| 🔴 결합 조회 차단 유지 | `missions.child_id` 는 `identity` 로 **FK 를 걸지 않았다**. `activity` 역할로는 아이 이름을 못 읽는다 (REQ-NF-009 · S3) |

**FK 를 안 건 대가** — 아이 행을 다시 만들면 미션이 **고아**로 남는다. 실제로 공유 개발 DB 에서
한 번 발생했다. 개발용으로 `app/prisma/seed-missions.mjs` 를 뒀다 — 아무것도 지우지 않고
현재 아이에게 미션만 다시 깐다. **운영에서는 아이 삭제 시 `activity` 정리 작업이 따로 필요하다 (미구현).**

**검증** — 실제 DB 대상 한 바퀴 전건 통과.

```
① 미실천 → ② 「했어요」: 잔액 그대로 (별 안 붙음)
③ 승인 1회 +2 · 2회째 P2002 거부 → 순증가 = 보상 (중복 0건)
④ 대기 중 되돌리기 성공  ⑤ 승인된 것 되돌리기 0건 (막힌다)
```

🔴 **아직 안 한 것** — 부모의 **미션 만들기** 화면이 없다. 지금은 시드로만 생긴다.

**설계에서 지킨 것**

여기가 그 자리다.

**검증** — 실제 DB 대상 전건 통과.


🔴 **아직 안 한 것** — 읽어 주기(음성)가 없다. 저학년은 글을 못 읽을 수 있다.
이모지와 짧은 문장으로 버티고 있지만 **접근성 요건으로 다시 봐야 한다.**

## D14 🔴 방·상점이 브라우저 localStorage 를 지갑처럼 쓰고 있었다

| 항목 | 내용 |
| --- | --- |
| 실제 | 별 잔액·보유 아이템·방 배치가 **브라우저**에 있었다 (`proto-store.ts` · `ff-proto-room-layout`) |
| 결과 | `activity.child_items` · `activity.child_room` 신설 (`20260831000010_child_items`) |

**왜 심각한가** — 기본값이 `별 40개 · 아이템 여러 개 보유`였다. 그래서 **오늘 가입한 아이가
이미 꾸며진 남의 방을 자기 방으로 봤다.** 게다가 별 원장에는 `WARDROBE_SPEND` 차감이 남는데
**무엇을 샀는지가 어디에도 없어** 원장과 화면이 서로를 몰랐다 — 정합성 검증이 불가능하다(REQ-NF-006).
기기를 바꾸거나 사생활 보호 모드로 열면 꾸민 방이 통째로 사라지기도 했다.

**설계에서 지킨 것**

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 별을 두 군데서 세지 않는다 | 잔액은 언제나 **원장의 합**이다. 상점이 따로 들지 않는다 |
| 🔴 별과 물건이 한 거래다 | `buyItem` 이 차감과 보유 등록을 함께 한다. 나뉘면 **별만 나가고 물건이 안 오는 아이**가 생긴다 |
| 🔴 두 번 눌러도 한 번 | 멱등키 `buy:<child>:<item>` (REQ-NF-003 오프라인 큐) |
| 🔴 빚을 지지 않는다 | 잔액 검사는 `grantStar` 안에서 원장 합을 보고 한다 |
| 🔴 안 가진 물건은 방에 못 둔다 | `saveLayout` 이 요청의 id 를 보유와 대조해 거른다 |
| 잠긴 것은 회색 | 숨기지 않는다 — 아이가 목표를 세울 수 있어야 한다 (사용자 결정) |

**카탈로그는 코드에 남긴다** — `contracts/items.ts`. GLB·썸네일 정의는 **에셋이지 회원 데이터가
아니다.** DB 는 「누가 무엇을 가졌는가」만 안다.

**`layout` 은 JSON 한 칸이다** — 방 안 좌표를 컬럼으로 펼치면 이름만 보고 **위치정보로
오해될 수 있다.** 규제 스캔 오탐을 피하려고 묶어 뒀다. 화면 좌표이지 위치 정보가 아니다.

**검증** — 실제 DB 대상 전건 통과.

```
① 새 아이 별 0 · 가진 것 0 (빈 방)   ② 별 0에서 사기 → 거부 (빚 안 짐)
④ 고양이(20) 구매 → 잔액 5           ⑤ 같은 것 재구매 → 두 번 안 나감
⑥ 토끼(25) → 모자라서 거부           ⑦ 안 가진 dog 를 방에 심기 → 걸러짐
```

🔴 **아직 안 한 것** — 아이템을 **되팔거나 환불하는 길이 없다.** 잘못 산 아이는 되돌릴 수 없다.

## D15 🔴 「배우기」에 배울 것이 없었다

| 항목 | 내용 |

| 실제 | 영역을 누르면 **곧장 퀴즈**로 갔다. 학습 콘텐츠가 한 편도 없었다 |

**고친 것**

| | |
| --- | --- |
| 학습 9편 (`contracts/lessons.ts`) | 벌기·잘 쓰기·모으기 각 3편. 한 편은 화면 하나를 넘지 않는다 |

| 흐름 | 배우기 → 영역 → 편 읽기 → (마지막 편) → 퀴즈. 예전엔 배우기 → 퀴즈였다 |
| 🔴 다시 읽어도 진도가 안 오른다 | 개수 대신 **읽은 편의 id 목록**을 담는다 (`completed_lessons`) |
| 🔴 읽기로는 별을 주지 않는다 | 주면 아이는 넘기기만 한다. SRS 트리거에도 없다 |
| 🔴 문항 수를 지어내지 않는다 | 총 수는 문항 은행이 센다. 틀린 문제는 다시 풀 수 있다 |

**콘텐츠는 코드에 남긴다** — 아이템 카탈로그와 같은 이유다. 글이지 회원 데이터가 아니다.
DB 는 **누가 무엇을 읽었는가**만 안다. `DAT-003` 이 콘텐츠를 DB 로 옮기면 모듈만 고치면 된다.

**검증** — 실제 DB 대상 전건 통과.

```
① 새 아이 진도 0행 (가짜 진도 없음)   ③ 같은 편 다시 읽기 → 안 오름
⑥ 같은 문항 다시 맞히기 → P2002 거부 · 별 그대로 · 퀴즈 수 안 부풂
```

🔴 **아직 안 한 것** — 읽어 주기(음성)가 없다. D13 과 같은 문제다.
「불리기(GROW)」는 여전히 잠겨 있다 — 실천 경로가 미개통이다.

## D16 🟠 「불리기」를 명세보다 더 잠갔다 · 별을 행동에 붙인다

### ① 불리기 — 학습까지 잠갔던 것

| 항목 | 내용 |
| --- | --- |
| SRS | **「불리기」는 학습만 열리고 실천은 닫혀 있다** (`isPracticeOpen(topic)` · AC-2.4) |
| 실제 | 영역 **전체**를 잠갔다. 아이가 **배울 기회조차 없었다** |
| 결과 | 학습·퀴즈를 열고 **실천만** 닫았다 |

**실천이 닫힌 이유는 진짜다** — 불리기의 실천은 **적금 가입~만기**다(GRW-001: 다른 영역은 매달
초기화, 불리기만 적금 시작~만기). 실제 금융상품과 카드 배송이 있어야 인정된다. 여기가 경계선이다.
**「곧 열려요」는 이제 실천에만 붙는다.**

🔴 실천 신청은 **서버에서도 막는다**(`claimPractice` 첫 검사). 화면만 감추면 요청은 그대로 통한다.

🔴 **금융상품을 권하지 않는다.** 불리기 3편은 이자의 원리 · 물가와 돈의 가치 ·
「늘 수도 줄 수도 있다」만 말한다. 특정 상품·투자처를 권하는 순간 교육이 아니라 권유가 된다.

### ② 별을 지식이 아니라 행동에 붙인다

| 항목 | 내용 |
| --- | --- |
| 이전 | 퀴즈를 틀리면 끝. 「다시 풀기」로 정답을 맞힐 때까지 반복 |
| 지금 | 틀리면 **설명만 보고 넘어간다.** 대신 배운 걸 하면 「해봤어요」로 별을 받는다 |

**왜** — 틀린 문제를 다시 풀게 하는 건 **정답 맞히기 연습**일 뿐이다. 이 제품의 규칙은
「배우고 → 해본다」이고, 별은 **행동**에 붙어야 한다.

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 여기서 별을 주지 않는다 | 보호자 승인 → `MISSION_APPROVED`. 아이가 자기 실천을 스스로 인정하면 실천 인정이 무의미해진다 |
| 🔴 한 편당 한 장 | `missions(child_id, source_id)` 부분 유니크. 두 번 눌러도 승인 대기가 두 줄로 안 는다 |
| 🔴 거절돼도 다시 신청 | 같은 줄을 되살린다. 한 번 거절로 영영 막히면 다시 해볼 이유가 없다 |
| 🔴 안 읽은 편은 안 보인다 | 배우기를 건너뛰고 별만 받아 가는 길이 된다 |
| 부모 화면이 출처를 가른다 | 「📚 아이가 배우고 스스로 함」. 같아 보이면 보호자는 자기가 시킨 줄 안다 |

### ③ 콘텐츠를 공개 자료 기반으로 다시 썼다

학습 12편 · 문항 12개. 근거는 `resources/` 의 두 자료다 — 금융감독원 「초등 3·4학년
금융생활 익힘책」, 「초등학교 슬기로운 생활금융」. **원문을 옮기지 않았다.** 개념과
**오개념**만 가져와 우리 문장으로 썼다.

오답 선택지가 특히 달라졌다. 예전엔 지어낸 뻔한 오답이었는데, 이제 자료가 실제로
교정하려는 오해를 쓴다 — 「돈 버는 방법은 직업뿐」 · 「먼저 쓰고 남으면 저축」 ·
「돈이 많아서 고민이 생긴다」 · 「투자는 저축보다 항상 많이 번다」.

### ④ 세 축을 4영역에 붙였다 — 5번째 영역을 만들지 않았다

자료가 크게 다루는 **신용 · 개인정보 · 위험** 축은 각각 제 자리가 있었다.

| 축 | 어디로 | 왜 |
| --- | --- | --- |
| 신용카드 | **잘 쓰기** | 카드는 **지불 수단**이다. 「공짜로 사는 것」이 아니라 「나중에 내가 내는 것」 |
| 이자의 양면 | **불리기** | 맡기면 받고 빌리면 낸다. 「빌린 돈으로 불리지 않는다」의 근거 |
| 개인정보 · 수상한 문자 | **모으기** | **모은 돈을 지키는 일**이다. 통장 비밀번호도 이미 여기 있다 |
| 위험 대비 | **모으기** | 자료도 저축하는 이유 중 하나로 든다. 별도 편 대신 `save-1` 에 한 줄로 넣었다 |

**왜 5번째 영역을 안 만들었나** — 영역을 늘리면 아이가 외워야 할 이름만 늘고,
**나무 승급 규칙(§6.2.1)을 다시 짜야 한다.** 4영역은 SRS 가 고정한 구조다.

이로써 **영역당 학습 4편 · 문항 4개**로 고르게 맞췄다 (16편 · 16문항).

🔴 **아직 안 한 것** — 보험 자체(보험료 ↔ 보험금 ↔ 약관)는 저학년에게 이르다고 보고
「대비해서 모은다」는 개념만 심었다. 고학년 확장 때 다시 볼 자리다.

## D17 🔴 아이 화면의 쓰기 경로가 끊겨 있었다 — 위시리스트 · 계획↔실제

두 화면이 **읽기 전용**이었다. 학습은 「여기 적어 두세요」라고 안내하는데 적을 데가 없었다.

### ① 위시리스트 (PRC-004)

| 이전 | 지금 |
| --- | --- |
| 추가·저금·삭제·순위 액션 **0개** | 목표 추가 · 모은 돈 넣기 · 지우기 · 순위 올리기(월 1회) |

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 재도달 중복 지급 0건 (REQ-TEC-011) | `reachedSteps` 는 줄어들지 않는다. 진행률이 내려갔다 올라도 두 번 안 준다 |
| 🔴 WPA 분자 산입 (PRC-004) | `PracticeCredit` 을 남긴다 — 퀴즈와 다른 점이다 |
| 자기 신고 한계 | 목표 5개 · 1,000~1,000,000원 · 1회 100,000원 |

**왜 한계가 필요한가** — 모은 돈은 **아이가 스스로 적는다**(용돈기입장과 같다).
한계가 없으면 100원짜리 목표를 계속 만들어 별을 무한히 받고, **실천 지표가 통째로 거짓이 된다.**

### ② 계획 ↔ 실제 (PLN-002 · PLN-003)

고리가 이렇게 끊겨 있었다.

```
계획 적기 ✅ → 계획 목록 ❌ → 실제로 쓴 돈 적기 ❌ → 회고 ⚠️(시드만)
```

계획은 `activity.plan_cards` 에 저장되는데 **아이가 다시 볼 화면이 없었고**,
`spending_records` 를 만드는 코드가 **어디에도 없었다.** 회고는 시드가 넣은 2건으로만 열렸다.

`/child/plan` 목록과 「얼마 썼는지 적기」를 만들어 닫았다.

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 ⭐ 판정은 **금액 단독** (ADR-008) | 업종이 달라도 금액을 지켰으면 준다. 섞으면 「업종이 달라서 별을 못 받았다」로 오해한다 |
| 🔴 넘겨도 **차감하지 않는다** (P-03) | 미지급일 뿐이다. 화면도 「넘겨도 괜찮아요」라고 말한다 |
| 🔴 계획 하나에 실제 하나 | 다시 적어 별을 또 받을 수 없다. 멱등키도 계획 id 다 |
| 🔴 지킴은 **실천**이다 | `PracticeCredit` 을 남긴다 (성장 나무 「계획 지키기」) |

**원래 설계는 실제 지출이 카드 연동(`DAT-004`)에서 온다.** 그게 붙기 전까지 손으로 적는다.

### ③ 함께 발견한 것 — `PracticeCredit` 을 아무도 안 쓰고 있었다

`modules/growth` 는 `practiceCredit` 을 읽는데 **쓰는 코드가 하나도 없었다.**
즉 **부모의 성장 나무가 영원히 0이었다.** 이번에 위시리스트 도달과 계획 지킴에서 남기기 시작했다.

🔴 **아직 안 한 것** — **미션 승인**(`approveMission`)이 아직 `PracticeCredit` 을 남기지 않는다.
미션이 실천의 주된 경로이므로 여기가 제일 크다. 승급 판정(GRW-001)도 여전히 없다.

**검증** — 실제 DB 대상 전건 통과.

```
위시리스트  8,000(33%)→⭐1 · 17,000(70%)→⭐2 · 24,000(100%)→⭐3
            0으로 내렸다 다시 100% → 새 단계 없음 (중복 0건)
계획↔실제   5,000 계획에 4,500 씀 → 지킴 ⭐1 · 같은 계획 재시도 → 거부
            2,000 계획에 3,500 씀 → 넘김, 별 그대로 (차감 없음)
            도서 계획인데 간식 8,000 → 지킴 ⭐ (업종 무관 · ADR-008)
```

## D18 🔴 용돈 장부 — 아이가 아무 숫자나 적던 것을 실제 잔액에서 빼게 한다

| 이전 | 지금 |
| --- | --- |
| 위시리스트 「모은 돈」을 아이가 **아무 숫자나** 적었다 | 보호자가 준 **용돈 잔액에서 떼어 온다** |
| 계획 실제 지출도 장부와 무관했다 | 쓴 만큼 용돈에서 빠진다 |

**결과** — `activity.allowance_ledger` 신설 (`20260831000013_allowance`) · 보호자 화면 `/parent/allowance`.

### 🔴 규제선 — 앱은 돈을 보관하지 않는다

사용자 요청은 「부모가 충전해준 카드에서 빠져나가게」였다. **충전식 선불카드는 만들지 않았다.**
앱이 실제로 가치를 보관하면 **선불전자지급수단**이 되어 전자금융업 등록 대상이고, 아동 명의
문제까지 겹친다.

대신 **장부**로 만들었다 — 실제 돈은 현금·보호자 카드로 앱 **밖에서** 오가고, 앱에는
「얼마 줬고 얼마 남았나」만 적힌다. 아이가 겪는 경험은 같다.
보호자 화면 **첫 카드가 이 사실을 그대로 말한다** — 오해를 만들면 안 된다.

### 🔴 별과 절대 섞이지 않는다 (P-21 · REQ-NF-010 · S4)

| 규칙 | 어떻게 |
| --- | --- |
| 전환 함수를 두지 않는다 | `modules/allowance` 는 `modules/star-ledger` 를 **import 하지 않는다.** 그 사실이 파일 첫 줄에서 보인다 |
| 표를 나눈다 | `star_ledger` ↔ `allowance_ledger`. 별로 용돈을 못 사고, 용돈으로 별을 못 산다 |
| 금지 심볼 회피 | `cash` · `withdraw` · `convert` 를 쓰지 않는다 (REQ-TEC-008 정적 검사) |

별이 나가는 곳은 여전히 **앱 내 재화(옷장·방 아이템)뿐**이다.

### 지킨 것

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 잔액을 저장하지 않는다 | 원장의 합이 잔액이다 — 별 원장과 같은 규율 (REQ-NF-006) |
| 🔴 0 밑으로 안 내려간다 | 없는 돈을 쓴 것으로 적으면 장부가 현실과 어긋나고, 그때부터 화면이 무의미해진다 |
| 🔴 중복은 정상 경로 | 멱등키로 막는다. 연타·오프라인 재전송이 두 번 빠지지 않는다 (REQ-NF-003) |
| 🔴 목표를 지우면 되돌린다 | 안 되돌리면 **아이 돈이 앱 안에서 사라진다.** 이미 받은 별은 되돌리지 않는다 — 그때 실제로 모았던 것은 사실이다 |

**부수 효과 — 별 farming 이 막혔다.** 예전엔 100원짜리 목표를 만들고 아무 금액이나 적어
⭐ 3개를 받을 수 있었다. 이제 **없는 돈은 못 넣는다.** 한계값으로 막던 것을 구조로 막는다.

**검증** — 실제 DB 대상 전건 통과.

```
② 20,000 받음  ③ 8,000 떼어 둠 → 12,000  ④ 같은 조작 재전송 → 두 번 안 빠짐
⑤ 50,000 시도 → 거부 (없는 돈 못 씀)     ⑥ 목표 삭제 → 20,000 복원 (돈이 안 사라짐)
⑦ 4,500 씀 → 15,500 · 별은 0 그대로 (두 원장이 안 섞인다)
```

### ⑤ 정정 — 줄을 고치지 않고 **반대 줄을 적는다** (추가 구현)

원장에서 줄을 수정·삭제하면 **「합이 잔액」이 깨지고 왜 이렇게 됐는지 아무도 못 본다.**
회계와 같이 상쇄하는 줄을 새로 적는다.

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 보호자가 적은 줄만 되돌린다 | `TOPUP` · `ADJUST` 만. 아이 기록을 보호자가 임의로 지우면 아이는 자기 장부를 못 믿는다 |
| 🔴 되돌릴 수 있는 만큼만 | 20,000원을 잘못 줬는데 아이가 15,000원을 이미 넣었으면 **5,000원만** 돌아온다 |
| 🔴 못 되돌린 만큼을 그대로 말한다 | 조용히 넘기면 보호자는 다 취소된 줄 안다 |
| 🔴 한 줄당 한 번 | 멱등키 `adjust:<줄id>` |
| 아이도 본다 | 「부모님이 고쳤어요 — 사유」. 잔액이 말없이 줄면 아이는 앱이 고장 난 줄 안다 |

**아이 용돈 기입장 `/child/allowance` 를 함께 만들었다.** 두 공개 자료가 **가장 강조하는
실천이 용돈기입장 쓰기**다 — 날짜·내용·들어온 돈·나간 돈·남은 돈 다섯 칸을 그대로 옮겼다.

## D19 🟠 카드 연동 — 예시 데이터로 흐름을 먼저 세운다

`activity.card_transactions` 신설 (`20260831000014_card_txn`) · `prisma/seed-card.mjs`.

**아직 실제 연동이 아니다.** `source = MOCK` 인 줄만 들어오고, 화면이 **「예시 · 카드 연동 전」**
이라고 밝힌다. 실제 연동(`DAT-004`)은 제휴 카드사가 발급하고 **자금은 카드사가 보관**한다 —
앱은 내역만 받는다. 그래야 D18 의 선(앱은 돈을 보관하지 않는다)이 유지된다.

### 🔴 카드가 손입력을 대체하지 않는다

두 공개 자료가 **가장 강조하는 실천이 용돈기입장 쓰기**다. 카드가 자동으로 적어 주면
**그 학습이 사라진다.** 편해지는 건 부모이지 아이가 아니다.

그래서 카드 내역은 **대조용**이다.

| | |
| --- | --- |
| 계획 화면 | 카드 내역을 눌러 금액을 채운다. **채운 뒤 고칠 수 있다** |
| 회고 화면 | 「적은 것보다 1,500원 더 썼네요」 — **자동으로 고쳐 주지 않는다** |

**차이를 마주하는 것이 학습 장면이다.** 시드가 카드 금액을 계획과 **일부러 어긋나게** 넣는다 —
딱 맞으면 대조할 게 없다.

🔴 한 거래는 **한 번만 쓰인다** (부분 유니크 인덱스). 같은 거래로 두 계획을 맞춰 별을
두 번 받을 수 없다.

**검증** — 실제 DB 대상 전건 통과.

```
정정  ② 그대로 되돌리기 20,000 → 잔액 0
      ④ 아이가 15,000 쓴 뒤 되돌리기 → 5,000만 · 못 되돌린 15,000 그대로 알림
      ⑤ 또 되돌리기 → 거부   ⑥ 아이 기록 고치기 → 거부   ⑦ 지운 줄 0
카드  ⑨ 카드 4,500 ↔ 아이가 적은 3,000 → 차이 1,500 (회고가 보여준다)
      ⑩ 같은 거래 재사용 → 0건
```

🔴 **아직 안 한 것** — 실제 연동은 **개발이 아니라 제휴 일정**이다(카드사 계약·심사).
마이데이터 방식은 본인신용정보관리업 허가가 필요하고 아동 계좌는 더 까다로워 후순위다.
영수증 OCR 은 **넣지 않는다** — AI 제약 위반이고, 금액 오인식이 곧 장부 오류가 된다.

### D20-b 승급 엔진 자리 — 단계를 읽는 대신 **읽는 시점에 계산한다**

| | |
| --- | --- |

**🔴 이자율 설정과 F15 는 다른 기능이다** — 이것을 한동안 하나로 묶어 답했다.

| | 이자율 설정 (이 항목) | F15 예적금 비교·선택 |
| --- | --- | --- |
| 누가 | **부모가 직접 이자를 준다** | 외부 금융상품을 비교·선택 |
| 상태 | SRS §3 에 명시 · 만들 수 있다 | `REQ-FUNC-014` **Could Have · Blocked (D2)** |
| 막는 것 | 없음. 단 **이자 주기가 D6 미결** | **P-20** 가입 중개 금지 · 법률 검토 대기 |

**🔴 지키고 있는 선**

- 잔액은 **우리 것이 아니다.** 선불충전금은 제휴사가 100% 별도관리한다(`ADR-004`).
  `mock_balance_won` 은 시연용 숫자이며 `PTN-001` 착수 시 버린다
- **금액을 직접 입력받지 않는다.** 5,000 / 10,000 / 30,000 버튼뿐이다 —
  입력란을 두면 실제 이체처럼 읽힌다
- **이자를 지급하지 않는다.** 주기가 `D6` 미결이므로 「한 번 줄 때」 금액만 계산해 보여준다.
  주기를 임의로 정하면 아이가 기대하는 시점과 어긋난다
- 화면 맨 위에 *"🔴 시연용 화면입니다. 실제로 돈이 옮겨지지 않습니다."*

**탭 구성이 바뀌었다** — D14 의 「미션」 탭이 **「통장」**이 됐다(나무 · 숲 · **통장** · 소비 · 내 정보).

`D6` 미결에 **이자 주기**가 이미 올라 있다 — 그것이 정해지면 지급 배치를 만든다.

## D20 🟠 아이 통장 — 부모만 보던 카드·이자를 아이도 본다

| 이전 | 지금 |
| --- | --- |
| `/child/allowance` 는 **잔액과 기록만** 보여줬다 | 쓸 수 있는 돈 · 목표에 넣어 둔 돈 · **카드 상태** · **이자** · 기록 |

부모 화면(`/parent/bank`)에는 **카드 발급 단계와 이자율이 있는데 아이 화면에는 없었다.**

**왜 이게 중요한가**

| | |
| --- | --- |
| **카드** | 부모가 신청했는데 아이는 **카드가 오는지 몰랐다.** SRS `UX-006` 의 「카드 배송 대기」는 원래 아이 화면 요소다 |
| **이자** | 「불리기」 `grow-1` 에서 **은행은 왜 이자를 줄까**를 배우는데, **정작 자기 이자를 못 봤다.** 배운 걸 자기 돈에서 확인하지 못하면 그 학습은 남의 이야기로 끝난다 |

**설계에서 지킨 것**

| 규칙 | 어떻게 |
| --- | --- |
| 🔴 결합 조회를 하지 않는다 (REQ-NF-009 · S3) | 보호자 행을 `guardianId` 로 **따로** 읽어 애플리케이션 계층에서 합친다. Prisma 관계를 타지 않는다 (ADR-T03) |
| 🔴 **아직 받은 이자가 아니다** | 「한 번 줄 때 얼마인지」만 보여주고 「부모님이 주실 때 붙어요. 아직 받은 건 아니에요」라고 적는다 — 지급 주기가 미정인데 자동으로 주는 것처럼 보이면 아이가 기다리는 시점과 어긋난다 |
| 두 숫자를 나란히 | 「쓸 수 있는 돈」과 「목표에 넣어 둔 돈」은 **다른 돈**이다. 하나로 합쳐 보여주면 아이가 다 쓸 수 있는 줄 안다 |
| 카드 5단계를 아이 말로 | 없음 · 신청했어요 · 확인 끝났어요 · **오고 있어요** · 쓸 수 있어요 |

**검증** — 용돈 12,000원 · 목표 8,000원 · 이자율 5% → 「지금이면 400원」 · 카드 「오고 있어요」.

🔴 **아직 안 한 것** — 부모 화면의 잔액이 **여전히 둘**이다
(`/parent/bank` 는 컬럼, `/parent/allowance` 는 원장). `/parent/bank` 에서 충전한 돈은
**아이 통장에 나타나지 않는다.** 정리는 `feat/parent-mission` 쪽에 넘겼다
(`[Ops]Handoff-Allowance-Ledger.md` · 2026-08-31 사용자 결정).
