## 0. 한 줄 요약

**화면 4개를 `npm run dev` 로 띄워 보는 것.** 그 이상은 하지 않는다.

| | 값 |
| --- | :-: |
| 작업 | **6가지** |
| 공수 | **6 person-day** |
| 기간 | **1명 6일 · 2명 4일** |
| 산출물 | 로컬에서 도는 화면 **3개** |

> 착수 전 인터뷰(§9)에서 화면 4개 → **3개**로 줄었다. 아동 홈은 **아바타 에셋이 D4 결정에 걸려** 제외했다.

## 1. 무엇을 하고 무엇을 안 하나

| | 한다 | 안 한다 |
| --- | --- | --- |
| 실행 | `npm run dev` **로컬만** | Vercel 배포 · 연결 |
| 데이터 | **하드코딩 상수** | DB · Prisma · Supabase |
| 화면 | 정적 렌더 + 시나리오 전환 | 로그인 · 동의 게이트 |
| 스타일 | Tailwind + shadcn/ui | 디자인 시스템 문서화 |
| 검사 | 없음 | `prebuild` 게이트 5종 |
| 그 밖 | — | 환경 변수 · 계측 · 테스트 · 알림 |

> **왜 이렇게까지 빼나** — 지금 확인하려는 건 **"이 화면이 말이 되는가"** 하나다.
> 나머지는 그 답이 나온 뒤에 붙여도 늦지 않다.

## 3. 화면 4개

기존 아트보드가 이미 있으므로 **새로 그리는 게 아니라 옮기는 것**이다.

| 화면 | 기존 아트보드 | 무엇을 확인하나 |
| --- | --- | --- |
| 🌳 **성장 나무** | `Tree.dc.html` | **5초 보고 「무엇이 달라졌는지」가 읽히는가** — 이 제품의 핵심 주장 |
| 💳 **계획↔실제 대조·회고** | `Review.dc.html` | **지킨 날과 넘긴 날이 화면만으로 구별되는가** |
| 🌲 **월간 숲** | `Forest.dc.html` | 전월 대비 변화가 60초 안에 3개 짚히는가 |
| ~~🐾 아동 홈~~ | ~~`Main.dc.html`~~ | ❌ **제외** — 아바타 에셋이 **D4 미결**이라 지금 만들면 다시 만든다 |

> **나무 → 대조 → 숲 순으로 만든다.** 앞의 둘이 이 제품의 두 차별점이다.
> 인터뷰 결정에 따라 **나무까지 먼저 만들어 확인받고** 나머지를 이어간다(§9 결정 5).

## 4. 🔴 목 데이터에 반드시 넣을 것

화면을 **정상 상태로만 보면 이 제품을 잘못 판단한다.**

| 시나리오 | 왜 필요한가 |
| --- | --- |
| **실천 0건 (빈 화면)** | 이 제품은 초기에 화면이 오래 비어 보인다. **가장 먼저 확인해야 할 화면이다** |
| **정체 14일** | 원인이 조건 단위로 읽히는가. 안 읽히면 보호자는 앱을 불신한다 |
| **전월 데이터 없음** | 첫 달. 델타 0으로 그리면 「변화 없음」으로 오독된다 |
| **계획 넘김** | 별이 안 붙는 쪽. 벌칙으로 읽히면 안 된다 |
| **별 잔액 부족** | 아동 홈의 잠금 상태 |
| 정상 | 위와 비교할 기준 |

**L6 시나리오 전환 UI가 필요한 이유가 이것이다.** 6가지를 드롭다운으로 즉시 바꿔 볼 수 있어야
인터뷰에서 한 세션에 다 보여줄 수 있다.

## 6. 끝나면 알 수 있는 것

| 실험 | 질문 | 통과선 |
| :-: | --- | :-: |
| **E1** | 나무를 5초 보고 행동 변화를 1문장으로 말하는가 | ≥ 6/8 |
| **E2** | *"나무가 자랐다는 건 뭘 했다는 뜻인가"* 에 **「실천」**이 나오는가 | ≥ 6/8 |
| **E5** | 정체를 보고 **아이 탓 · 앱 불신** 발화가 나오는가 | 각 ≤ 2/8 |
| **E8** | 회고 두 갈래가 화면만으로 구별되는가 | ≥ 6/8 |

**E1이 3/8 이하면 나무 UI를 다시 그린다.** 백엔드를 다 만든 뒤에 알게 되는 것보다 훨씬 싸다.

## 9. 착수 전 인터뷰 결정 (2026-08-26)

에이전트가 착수하기 전에 미확정 사항을 확인했다. **아래는 확정이며 다시 묻지 않는다.**

| # | 사항 | 결정 | 근거 |
| :-: | --- | --- | --- |
| **1** | 코드 위치 | **같은 저장소 `app/` 하위** | 문서와 코드가 한곳에 있어 태스크 명세를 보며 작업한다. `.gitignore` 에 `node_modules` 추가 |
| **2** | 나무 단계 수 (**D6 미결**) | **3단계 씨앗·새싹·나무** · 화면에 **「예시값」 표시** | 설계 문서 SM-03과 기존 아트보드가 이미 3단계다. **D6은 계속 미결로 둔다** |
| **3** | 아바타 에셋 (**D4 미결**) | **아동 홈 화면 제외** | 에셋이 D4에 걸려 있어 지금 만들면 어차피 다시 만든다 |
| **4** | 뷰포트 | **모바일 폭 고정**(390px) · 데스크톱에서 가운데 정렬 | 실제 사용 맥락과 같고 인터뷰에서 폰처럼 보여줄 수 있다 |
| **5** | 착수 범위 | **나무까지 먼저 만들어 확인** → 대조 · 숲 | 방향이 틀렸을 때 재작업을 3개가 아니라 1개로 막는다 |
| **6** | 시나리오 전환 | **화면 상단 드롭다운** | 인터뷰 진행자가 즉시 전환한다. 나중에 그 바만 지우면 끝난다 |
| **7** | 목 데이터 값 | **기존 아트보드 값 그대로** | 팀이 이미 본 값이라 비교가 쉽다 |
| **8** | Tailwind 버전 | **v4** | shadcn/ui 공식 지원 · `create-next-app` 기본값. 되돌릴 일 없는 기술 선택이라 묻지 않았다 |

### 인터뷰에서 해소된 것 — 문구는 막히지 않는다

착수 전 **「회고 문장이 없다(D3 콘텐츠 원고 미결)」** 를 블로커로 의심했으나, **기존 아트보드에 한글 문구가 이미 있다.**

| 화면 | 아트보드에 있는 문구 |
| --- | --- |
| 대조·회고 | *"적은 대로 잘 썼어요"* · *"계획보다 N원 더 썼어요"* · *"적어둔 돈 N원"* |
| 나무 | *"퀴즈만으로는 자라지 않습니다"* · *"각 단계마다 행동 실천 횟수"* |
| 숲 | *"이번 달 한 줄 — 쓰기와 모으기가 함께 자랐습니다"* |

**D3은 프로토타입을 막지 않는다.** 문장 풀의 다양성(재노출률)은 운영 4주 실측 대상이라 범위 밖이다.

| :-: | --- |
