> ## 🔴 v2.0 — 화면 모형에서 라우트 앱으로
>
> v1.x는 **한 페이지에 폰 3개를 나란히 놓고 드롭다운으로 상태를 바꾸는** 모형이었다.
> v2.0은 **라우트 13건을 실제로 이동하는 앱**이다. 상태 전환 드롭다운은 없어졌고,
> 대신 **아이(Fun) · 보호자(Clean) 두 모드**가 같은 토큰 이름을 다른 값으로 갖는다.
>
> **왜 바꿨나** — 화면 3개를 나란히 보면 *"이 제품이 어떻게 생겼나"* 는 알 수 있지만
> *"아이가 어디서 출발해 어디로 가나"* 는 알 수 없다. 동선이 없으면 인터뷰에서 물어볼 게 없다.
> 그리고 아동 화면과 보호자 화면은 **같은 컴포넌트로 만들되 톤이 갈려야** 하는데,
> 한 페이지 모형에서는 그 차이를 세울 자리가 없었다.

### 4.2.1 🔴 아바타 회전을 CSS 3D 로 만든 이유

ADR-T05가 3D → Lottie 2.5D 전환의 대가로 *"**회전이 사라진다**"* 를 적어 뒀고,
그 전환은 **D4와 함께 아직 승인 전**이다. 승인 여부를 판단하려면 **회전이 있는 화면을 먼저 봐야 한다.**

그래서 렌더러를 추가하지 않고 `transform-style: preserve-3d` + `rotateY` 로만 세웠다.

| | |
| --- | --- |
| 의존성 추가 | **0건** — REQ-TEC-007(UI 의존성 0건 · Lottie 예외 1건)을 건드리지 않는다 |
| 번들 증가 | **0KB** |
| D4 · B4 게이트 | 건드리지 않는다 — 3D 에셋 제작을 되살리지 않는다 |
| 확인하려는 것 | **회전이 아이에게 의미가 있는가** 하나 |

**three.js 도입은 이 화면으로 회전의 값어치를 확인한 뒤에 판단한다.**
도입한다면 REQ-TEC-007 예외를 2건으로 늘리는 결정이므로 §8 충돌 대장 X2와 ADR-T05를 함께 고쳐야 한다.

전환은 `.ff-avatar-spin` 클래스가 갖는다 — 인라인 `transition` 을 쓰면
`prefers-reduced-motion` 이 걸리지 않는다.

### 4.3 모션

CSS 전용이다. **Lottie · GSAP 을 설치하지 않는다** — 로컬 최소안 §2에서 정적 표현으로 대체하기로 했다.
`.ff-star-earn` 은 `var(--ff-star-anim)` 을 쓴다 — **컴포넌트를 고치지 않고 토큰으로 가른다.**
`prefers-reduced-motion` 에서 둘 다 끈다.

> **`next/font` 를 쓰지 않는다.** 한글 웹폰트는 용량이 커 로컬 확인을 느리게 만든다.
> 시스템 스택으로 충분하고, 아트보드도 같은 스택이다.

## 5. 컴포넌트 인벤토리 <!-- T5 -->

**shadcn/ui 자체 구현 금지**(D-08 · REQ-TEC-007). 다만 이 프로토타입의 화면은 폭 390px에
밀도가 높아 shadcn 기본 패딩을 전부 덮어써야 했다. 그래서 **프레임 내부는 토큰 기반 소형
컴포넌트로 짜고, shadcn 설치는 유지한다** — 본 개발의 데스크톱·폼 화면에서 쓸 자리가 있다.

### 5.1 직접 만든 것 — 화면 규율을 강제하는 것만

| 컴포넌트 | 무엇을 강제하나 |
| --- | --- |
| `shared/ModeFrame` | **`data-mode` 를 다는 유일한 곳** · 390px 폭 · 가운데 정렬 |
| `shared/Screen` | 화면 머리 순서 — 역할 → 제목 → 부제 |
| `shared/Empty` | **빈 화면 금지** — 안내 + 다음 행동 (ACE-1.1) |
| `shared/Card` | 톤 3종 — `surface` · `miss`(테라코타) · `grow`(초록) |
| `parent/TreeArt` | 단계별 정적 표현 · **Lottie 없음** (D6 예시값) |
| `parent/InactivityBanner` | 정체를 **조건의 문제**로 쓴다 (AC-3.2) |
| `child/StarHUD` | 별 잔액 · fun 모드에서만 튄다 |
| `child/Avatar` | **D4 미결 대체물** — 이모지 조합 + **CSS 3D 회전**. 에셋이 오면 이 파일만 갈아끼운다 |

### 5.2 shadcn 설치본 7종

`alert` · `badge` · `button` · `card` · `progress` · `select` · `separator`
스타일 프리셋 `base-nova`. 목록 밖이 필요하면 **추가 전에 원장에 토픽으로 올린다.**

## 6. 픽스처 규약 <!-- T6 -->

### 6.1 목은 화면 옆에 산다

```
app/src/app/parent/tree/tree.fixture.ts      ← 화면 옆
app/src/app/child/retro/[recordId]/retro.fixture.ts
```

**`src/mocks/` 같은 최상위 디렉터리를 만들지 않는다.** 화면과 목이 떨어져 있으면
교체할 때 어느 화면이 어느 목을 쓰는지 매번 추적해야 한다.

### 6.2 첫 줄에 교체 지점을 적는다

```ts
// PROTO-DATA: GRW-003 — 백엔드 완료 시 이 파일을 지우고 GRW-001 · GRW-002 호출로 대체한다
```

**모든 `*.fixture.ts` 의 첫 줄이 이 형식이다.** 후행 태스크가 `grep -rl 'PROTO-DATA:'` 한 번으로
교체 지점을 전수 특정한다. 하나라도 빠지면 그 등식이 깨진다 — `verify_proto_structure.py` 가 센다.

| 화면 | fixture | 교체 대상 |
| --- | --- | --- |
| `/parent/tree` | `tree.fixture.ts` | `GRW-001` 나무 상태 · `GRW-002` 정체 판정 |
| `/parent/forest` | `forest.fixture.ts` | `GRW-004` 숲 스냅샷 |
| `/parent/missions` | `mission.fixture.ts` | `PRC-001` 미션 루프 · `PRC-003` 일괄 승인 |
| `/parent/spending` | `spending.fixture.ts` | `PLN-005` 소비 내역 집계 |
| `/parent/onboarding` | `onboarding.fixture.ts` | `CON-003` 온보딩 세션 저장 |
| `/consent` | `consent.fixture.ts` | `CON-002` 동의 게이트 서버 판정 |
| `/child/home` | `home.fixture.ts` | `STR-003` 옷장 · 별 잔액 |
| `/child/learn` | `learn.fixture.ts` | `LRN-001` 커리큘럼 |

### 6.3 타입을 계약 파일에 선취하지 않는다

타입은 **화면 로컬**에 둔다. `src/contracts/` 는 `CTR-002` 의 소유이며,
프로토타입이 먼저 채우면 본 개발이 그것을 고쳐야 한다. `CTR-002` 가 끝나면 `import` 만 갈아끼운다.

### 6.4 값의 출처

아트보드 값을 그대로 쓴다 — **서연 · 2026년 3월 · 다이소 성수점 · 문구 5,000원**.
4영역은 벌기 나무 · 잘 쓰기 새싹(정체 14일) · 모으기 씨앗 · 불리기 잠금.

## 7. 확인 도구 <!-- T7 -->

### 7.1 라우트로 이동한다

v1.x의 상태 드롭다운은 없앴다. **화면이 라우트로 갈리므로 주소가 곧 상태다.**
두 갈래를 비교해야 하는 회고만 레코드 ID로 가른다 — `r-201` 지킴 · `r-202` 넘김.

색인 `/` 에 라우트 13건이 두 모드로 나뉘어 있고, **각 항목에 담당 태스크 ID가 붙어 있다.**
🔴 프로토타입 전용이다. 본 개발에서 지운다.

### 7.2 뷰포트

**모바일 폭 390px 고정**(`--ff-frame`). 데스크톱에서는 가운데 정렬한다.
프레임 바깥은 body 색(`#ECE8E1`)이라 어디까지가 화면인지 눈으로 갈린다.

### 7.3 스크린샷

`reports/proto/` 에 **라우트 13건 + 색인 1장 + 회고 두 갈래 1장 + 아바타 뒷모습 1장 = 16장**.

```
index.png
consent.png  parent-onboarding.png  parent-tree.png  parent-forest.png
parent-missions.png  parent-spending.png
child-home.png  child-home-back.png  child-learn.png  child-quiz.png  child-plan-new.png
child-retro-met.png  child-retro-over.png  child-wishlist.png  child-stars.png
```

**촬영은 손으로 하지 않는다.**

```sh
cd app && npm run build && npx next start -p 4312 &
tools/shoot_proto.sh          # 촬영 → tools/trim_shots.py 로 하단 여백 정리
```

아바타 뒷모습은 `?face=back` 으로 찍는다 — 🔴 촬영 전용 통로이며 UI 가 아니다.

`next dev` 로는 찍히지 않는다 — HMR 웹소켓이 열려 있으면 헤드리스 크롬이 종료되지 않는다.
