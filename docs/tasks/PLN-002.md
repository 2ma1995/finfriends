## ✅ Task Breakdown (실행 계획)
- [ ] 결제 발생 시 계획 카드 자동 매칭 (가맹점명 또는 업종 일치)
- [ ] 복수 결제는 **합계로 판정** · 업종별 내역 나열
- [ ] 매칭 정확도 계측 · 수동 대조 표본 50건 대조
- [ ] 계획 카드 없는 결제 → `NO_PLAN` 분기
- [ ] **판정은 금액 단독** — 업종 불일치는 ⭐를 막지 않는다 (ADR-008)

## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 자동 매칭 정확도가 90% 이상이다
- Given: 계획 카드가 존재하는 아동에게
- When: 카드 결제가 발생하면
- Then: 자동 매칭되고 정확도 **≥ 90%** (AC-4.2)

Scenario 2: 복수 결제는 합계로 판정된다
- Given: 한 계획 카드에 여러 결제가 매칭된 상태에서
- When: 대조 화면을 만들면
- Then: **합계로 판정**하고 업종별 내역을 모두 나열한다 (ACE-4.1)

Scenario 3: 실패 흐름 — 계획 없는 결제
- Given: 계획 카드가 없는 상태에서 결제가 발생하면
- When: 아동이 앱을 열면
- Then: 대조 화면 대신 **작성 유도**가 노출되고 **⭐가 지급되지 않는다** (AC-4.3)

## ⚙️ Technical & Non-Functional Constraints
- 외부 의존: **D1** 업종 코드 상세도. 낮으면 정확도 90%가 성립하지 않는다 (ADR-004).
- 설계: **ADR-008** 금액 단독 판정. `category_met` 은 관측 항목이다.
