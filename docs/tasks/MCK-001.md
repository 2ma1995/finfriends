## 🧪 Acceptance Criteria (BDD/GWT)

Scenario 1: 네 화면이 같은 값을 본다
- Given: 나무와 숲을 같은 목으로 렌더한 상태에서
- When: 실천 횟수를 비교하면
- Then: **두 화면의 값이 일치**한다. 화면별로 다른 목을 두지 않는다

Scenario 2: 빈 상태를 렌더할 수 있다
- Given: 빈 상태 픽스처를 선택한 상태에서
- When: 네 화면을 연다
- Then: **델타 0으로 렌더되지 않고** 안내 문구가 나온다 (ACE-1.1 · ACE-1.2)

Scenario 3: 실패 흐름 — 목이 운영에 새지 않는다
- Given: 운영 빌드에서
- When: 픽스처 모듈 참조를 검사하면
- Then: **0건**이어야 한다. 목은 프로토타입·개발 환경에서만 로드된다

## ⚙️ Technical & Non-Functional Constraints
- 범위: **프로토타입 전용**이다. 실제 데이터 접근이 완료되면 해당 픽스처를 제거한다.
- 형태: 픽스처는 **중립판 §6.2의 열거형**을 따른다. 임의 필드를 만들지 않는다.
- 규제: 목 데이터에도 **위치 좌표 · 얼굴 이미지를 넣지 않는다** — 스키마 스캔 대상이다.
