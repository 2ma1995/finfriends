# 003 — 개발 규범

## 실패를 표현하는 방법

```
ActionResult<T> = { ok: true; data: T } | { ok: false; code: ErrorCode; message: string }
```

- **예외를 던져 실패를 표현하지 않는다.** 검증 실패는 5xx가 아니다 — 오류율(≤ 0.5%)에 섞이면 안 된다
- 응답에 **스택 · 내부 경로 · SQL을 담지 않는다**
- 인가 확인은 **각 액션의 첫 줄**

## 트랜잭션

- 상태 변경과 **계측 이벤트를 같은 트랜잭션**에 넣는다. 따로 적재하면 **롤백된 실천이 지표에 남는다**
- **트랜잭션 안에서 외부 호출을 하지 않는다** — 제휴사 API·푸시 발송은 커밋 뒤에
- 별 증감은 **이중 기입** + `idempotency_key` 유니크 제약

## 멱등

아래는 전부 재요청·재수신·재실행될 수 있다. **부작용이 1회만** 나야 한다.

| 대상 | 키 |
| --- | --- |
| ⭐ 지급 · 차감 | `idempotency_key` |
| 결제 웹훅 | 결제 식별자 |
| 배치 실행 | `run_key` |
| 오프라인 큐 flush | 클라이언트 생성 키 |

## 시간

- 주차 귀속은 **`client_ts` 기준**이다. 서버 도착 시각으로 귀속하면 오프라인 기간 실천이 다음 주로 밀린다
- 주차는 **ISO 주(월~일) · KST**
- 소급 지급은 **완료 시점 주기에 귀속**한다. 지급 시각으로 계산하면 다음 주기 나무가 부풀려진다

## 화면

- 빈 상태를 **델타 0으로 렌더하지 않는다.** 안내 문구로 대체한다
- 아동 화면에 **성장 나무를 두지 않는다** — 정보 과부하다. 아동의 동기 장치는 옷장이다
- 회고에서 아동이 하는 것은 **[확인했어요] 한 번**이다. 작성·선택·입력을 요구하지 않는다
- 아동 노출 문구는 **알기 쉬운 언어**가 법정 의무다. 검수 대상으로 등록한다

## 지표를 오염시키지 않기

| 하면 안 되는 것 | 왜 |
| --- | --- |
| 학습 경로 트리거를 WPA 분자에 넣기 | 접속만으로 지표가 올라 **활동량 지표로 퇴화** |
| 온보딩 직후 계정을 분모에 넣기 | **가입이 늘수록 WPA가 떨어진다** |
| 푸시 차단 계정을 도달률 분모에 넣기 | 채널 문제가 **제품 문제로 보인다** |
| 실측 전 목표값을 성과로 표기 | 기준선은 실측 전이다 |

## 테스트

- **실패 흐름을 반드시 테스트한다.** 태스크 명세의 Scenario 중 「실패 흐름」이 그것이다
- 규제 항목(허용 오차 0)은 **위반 픽스처**로 검증한다 — 정상만 통과시키면 검사가 작동하는지 알 수 없다
- 인터뷰 지표(`k/8`)는 **테스트가 아니라 실험 절차**다. 자동 통과로 처리하지 않는다

## 문서

- 태스크 리스트 · 이슈 명세 · 실행 계획은 **생성물이다.** 손으로 고치지 않는다
- 고칠 것은 `tools/tasks_data.py` · 고친 뒤 생성기를 돌린다
- 디렉터리를 옮겼으면 **`python3 tools/verify_links.py`** 를 돌린다
