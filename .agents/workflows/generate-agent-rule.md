# 워크플로 — 에이전트 규칙 추가

새 규칙(스킬·서브에이전트)을 만들 때의 절차다.

## 어디에 만드나

| 성격 | 위치 |
| --- | --- |
| 도구 공통 규칙 | `.agents/rules/` |
| 상황별로 꺼내 읽는 지침 | `.agents/skills/<번호-이름>/SKILL.md` |
| 특정 영역 전담 에이전트 | `.claude/agents/<이름>.md` |

**Claude Code용 심링크**를 함께 만든다.

```bash
ln -s ../../.agents/skills/<이름> .claude/skills/<이름>
```

## 번호 규칙

| 대역 | 성격 |
| --- | --- |
| 100~ | 개발 프로세스 (오류 · 빌드) |
| 200~ | 협업 (커밋 · 주석 · 이슈) |
| 300~ | **제약 가드레일** — 이 프로젝트의 핵심 |
| 400~ | 실행 절차 |

## 작성 규칙

- **프론트매터에 `name` 과 `description`** 을 둔다. `description` 은 **언제 읽어야 하는지**를 적는다
- 짧게 쓴다. 에이전트가 전부 읽지 않는다
- **금지 항목에는 대안을 함께** 적는다. 금지만 하면 우회한다
- **왜 금지인지**를 한 줄로 적는다. 이유를 모르면 지키지 않는다
- 우리 문서의 ID(`REQ-TEC-002` · `ADR-T02` · `P-21`)를 인용한다 — 근거를 되짚을 수 있어야 한다

## 검토

새 규칙이 **기존 규칙과 충돌하지 않는지** 확인한다. 특히 `300-tech-constraints-guardrails` 는
다른 모든 규칙보다 우선한다.
