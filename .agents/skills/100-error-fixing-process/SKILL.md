# 오류 수정 절차

## 1. 순서

```
1. 오류 메시지를 끝까지 읽는다 — 추측하지 않는다
2. 재현한다 — 재현 안 되면 아직 고칠 수 없다
3. 원인을 특정한다
4. 고친다
5. 재현 케이스를 테스트로 남긴다
```

**증상을 덮지 않는다.** try/catch로 감싸 조용히 넘기는 것은 수정이 아니다.

## 2. 이 프로젝트에서 자주 나는 오류

| 증상 | 흔한 원인 |
| --- | --- |
| 마이그레이션이 걸린다 | `DIRECT_URL` 대신 풀러로 실행 |
| 커넥션 고갈 | 앱이 직결 포트를 씀 |
| 빌드 실패 — 모듈 경계 | `index.ts` 외 경로로 교차 import |
| 빌드 실패 — 금지 심볼/필드 | 좌표·얼굴·전환 경로가 들어옴. **우회하지 말고 지운다** |
| 별이 두 번 지급됨 | `idempotency_key` 누락 |
| 지표가 실제보다 높음 | 이벤트를 상태 변경과 **다른 트랜잭션**에서 적재 |
| Cron이 안 돈다 | `X-Cron-Secret` 불일치 → 404 (정상 동작이다) |
| WPA가 낮게 나옴 | 분모에 계정 7일 미경과가 섞임 |

## 3. 실패를 표현하는 방법

```
❌ throw new Error("...")            5xx로 새어 오류율을 오염시킨다
✅ return { ok: false, code, message }
```

응답에 **스택 · 내부 경로 · SQL을 담지 않는다.**

## 4. 규제 검사가 실패했을 때

**우회하지 않는다.** 검사가 옳고 코드가 틀렸다.

`prebuild` 5종 중 금지 심볼·금지 필드 실패는 **규제 위반**이다. 플래그로 감싸도 여전히 실패한다.
설계를 바꿔야 하면 사람에게 묻는다.
