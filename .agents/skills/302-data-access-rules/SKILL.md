# 데이터 접근 규칙

**가장 자주 나는 사고 세 가지를 먼저 확인한다.**

1. **커넥션 문자열을 바꿔 쓰지 않는다** — 런타임은 `DATABASE_URL`(풀러), 마이그레이션은 `DIRECT_URL`(직결)
2. **새 테이블에는 RLS 정책을 같은 변경에 함께 넣는다** — 나중에 붙이면 그 사이가 구멍이다
3. **두 스키마를 조인하지 않는다** — `identity` × `activity` 결합 조회는 **규제 위반**이다

---

## 1. 스키마 분리 — 규제 요건이다

| 스키마 | 테이블 |
| --- | --- |
| `identity` | `guardian_accounts` · `child_accounts` |
| `activity` | `learning_progress` · `practice_credits` · `star_ledger` · `tree_states` · `forest_snapshots` · `plan_cards` · `spending_records` · `wishlists` · `app_events` |

**앱 역할은 두 스키마를 동시에 조인할 수 없다.** 화면이 아동 이름을 필요로 하면
**애플리케이션 계층에서 합친다.** 조인으로 우회하지 않는다.

결합 조회는 **감사 로그(S3)에서 검출**되고 즉시 알림이 된다. 허용 오차 0이다.

## 2. 금지 필드 — 부재가 설계다

| 필드 | 이유 | 검사 |
| --- | --- | :-: |
| 위치 좌표 | 위치정보를 **일절 수집하지 않는다**(ADR-002) | S1 · `prebuild` |
| 얼굴 이미지 | P-13 | S2 · `prebuild` |
| 별↔저금통 전환 | P-21 — **기능 플래그로 막는 방식 금지** | S4 · `prebuild` |

**추가하면 빌드가 실패한다.** 필요해 보이면 그것은 요구사항 변경이다.

## 3. 커넥션

```
DATABASE_URL   앱 런타임 — 풀러(트랜잭션 모드)
DIRECT_URL     마이그레이션 — 직결
```

**두 값이 같으면 안 된다.** 풀러의 트랜잭션 모드에서 마이그레이션을 돌리면 깨진다.

## 4. 멱등과 정합성

- `star_ledger` · `app_events` 에 **`idempotency_key` 유니크 제약**
- 별 증감은 **이중 기입** — 일일 정산 배치가 대조한다
- **정합성 오류율 0%는 협상 불가**다. 재설정 트리거를 두지 않는다
- **트랜잭션 안에서 외부 호출을 하지 않는다** — 제휴사 API·푸시는 커밋 뒤에

## 5. 파티셔닝

`app_events` 는 **주차 단위 선언적 파티셔닝**이다.

- Prisma가 파티션을 관리하지 못하므로 **생성·회전을 raw SQL 마이그레이션**으로 둔다 (REQ-TEC-004 예외)
- 회전은 `/api/cron/*` 에 등록한다
- **앱 코드의 raw SQL은 `prebuild` 가 막는다.** 예외는 마이그레이션·파티션 관리 경로뿐이다

## 6. 마이그레이션

- 스키마 변경은 **항상 마이그레이션 파일로** 남긴다
- 파괴적 변경은 **두 단계로** 나눈다 — 추가 → 이행 → 제거
- **운영 마이그레이션은 승인 없이 돌리지 않는다**
- RLS 정책을 **테이블 생성과 같은 마이그레이션**에 넣는다

## 7. 주차 귀속

이벤트의 주차는 **`client_ts` 기준**이다. 서버 도착 시각으로 귀속하면
**오프라인 기간의 실천이 다음 주차로 밀려 WPA가 왜곡된다.**
