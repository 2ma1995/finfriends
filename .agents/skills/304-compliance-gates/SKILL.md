# 규제 게이트

**아동 대상 금융 서비스다. 규제는 성능보다 우선하는 상수다.**

아래 항목은 *"낮게 유지"* 가 아니라 **"없음"** 이 기준이다. 허용 오차가 0이다.

---

## 1. 허용 오차 0인 항목 7가지

| # | 항목 | 기준 | 검사 | 위반 시 |
| :-: | --- | :-: | --- | --- |
| 1 | 동의 전 아동 화면 진입 | **0건** | `consent_gate_blocked` 실시간 | 즉시 알림 · 30분 내 확인 |
| 2 | 위치 좌표 필드 (S1) | **0건** | 스키마 스캔 · 배포 시 + 일 1회 | **빌드 실패** |
| 3 | 얼굴 이미지 필드 (S2) | **0건** | 스키마 스캔 | **빌드 실패** |
| 4 | 스키마 결합 조회 (S3) | **0건** | 쿼리 감사 로그 · 일 1회 | 즉시 알림 |
| 5 | 별↔저금통 전환 경로 (S4) | **0건** | 정적 분석 · CI 게이트 | **빌드 실패** |
| 6 | 아동 독립 로그인 시도 (S5) | **0건** | 인증 로그 · 일 1회 | 즉시 알림 |
| 7 | 별 원장 정합성 오류 | **0%** | 이중 기입 + 일일 정산 | 30분 내 확인 · 1시간 내 원인 특정 |

추가로 **⭐ 소급 지급 성공률 100%** 가 불변값이다. 보호자의 지연이 아동의 실패로 기록되면 안 된다.

## 2. 동의 게이트 — 가장 자주 잘못 구현되는 곳

```
❌ 클라이언트에서 동의 상태를 확인하고 화면을 감춘다
✅ 서버가 아동 화면 진입마다 판정한다
```

- 아동 화면은 **첫 진입부터 개인정보 처리가 시작**되므로 **순서 자체가 규제 요건**이다
- **동의를 캐시하지 않는다.** 세션 만료 시 재확인한다
- 차단 이벤트를 적재한다 — 1건 이상이면 **즉시 알림**

## 3. 별의 세 가지 금지선

| 금지 | 이유 |
| --- | --- |
| 현금으로 별 충전 | 대가 지급 취득 → 금전적 가치가 된다 |
| 별을 현금으로 환급 | 동일 |
| 별 양도 · 거래 · 선물 | "이전 가능" 요건 충족 |

**별과 저금통은 완전히 분리된 재화**이며 교차 지점이 없다.
**기능 플래그로 막는 방식은 허용되지 않는다** — 플래그는 켜질 수 있다. **경로 자체를 두지 않는다.**

> 계획을 넘겨도 **별을 차감하지 않는다.** 벌칙이 아니라 미지급이다(P-03).

## 4. 아동 계정

- **독립 자격증명을 갖지 않는다.** 보호자 세션 하위 프로필로만 존재한다
- 외부 공유 · 친구 기능 없음
- 보호자 세션이 만료되면 아동 화면이 잠긴다

## 5. 문구 — 법정 의무

아동에게 노출되는 고지·문구는 **알기 쉬운 언어**여야 한다(P-12 · 개인정보 보호법 제22조의2 제3항).

- 4영역 명칭은 **보호자·아동 동일**하게 둔다
- 새 문구를 만들면 **검수 대상으로 등록**한다
- 생성형 결과물을 아동에게 노출할 경우 **생성 파이프라인에 검수를 적용**한다

## 6. 그 밖의 규제 상수

| P-20 | 예적금 **가입 중개 안 함** — 비교·선택 경험까지만 |
| F-01 | 만 14세 미만 마이데이터 불가 → **자체 카드 발급 + 폐쇄형 수집** |

## 7. 검사 픽스처를 반드시 둔다

규제 검사는 **정상 케이스만 통과시키면 작동하는지 알 수 없다.**

각 검사에 **위반 픽스처**를 붙인다 — 좌표 필드를 추가한 스키마, 전환 함수를 넣은 코드,
플래그로 감싼 전환 코드. **전부 빌드를 실패시켜야 한다.**
