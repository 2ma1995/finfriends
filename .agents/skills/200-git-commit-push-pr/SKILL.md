# 커밋 · 푸시 · PR

## 1. 커밋 메시지

```
<타입>: <무엇을 했는가 — 한 줄>

<왜 했는가 · 무엇이 바뀌었는가>
<검증 결과>
```

| 타입 | 언제 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 결함 수정 |
| `refactor` | 동작 그대로 구조 변경 |
| `docs` | 문서 |
| `test` | 테스트 |
| `chore` | 도구 · 설정 |

**무엇을 했는지가 아니라 왜 했는지를 적는다.** 무엇은 diff가 말한다.

## 2. 태스크와 연결한다

이슈 번호를 본문에 남긴다. 태스크 ID도 함께 적으면 문서와 대조된다.

```
feat: 별 원장 엔진 — 트리거 8종 · 이중 기입 · 멱등

STR-001 (#20). 정합성 오류율 0%가 협상 불가이므로
idempotency_key 유니크 제약과 이중 기입을 함께 넣었다.

멱등 재요청 테스트 통과 · 원장 불일치 0건
```

## 3. 커밋 전에

- [ ] `prebuild` 게이트 5종 통과
- [ ] 테스트 통과
- [ ] **생성물을 손으로 고치지 않았는가** — 태스크 리스트 · 이슈 명세 · 실행 계획
- [ ] 문서를 옮겼다면 `python3 tools/verify_links.py`

## 4. 하지 말 것

| 금지 | 이유 |
| --- | --- |
| 시크릿 · `.env` 커밋 | 저장소가 **PUBLIC** 이다 |
| 생성물 직접 수정 후 커밋 | 다음 생성 때 덮인다. `tools/tasks_data.py` 를 고친다 |
| 게이트 우회 커밋 | 게이트가 옳고 코드가 틀렸다 |
| 요청 없는 push | 사용자가 요청할 때만 |

## 5. PR

- 제목에 **태스크 ID**를 넣는다
- 본문에 **AC 충족 여부**를 적는다 — 특히 **실패 흐름**
- 규제 항목을 건드렸으면 **어떤 검사로 확인했는지** 적는다
